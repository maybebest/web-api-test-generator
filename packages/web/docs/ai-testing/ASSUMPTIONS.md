# Implementation Assumptions

- Node 20 or newer and npm workspaces are the supported runtime; CI uses Node 22.
- Playwright starts the dependency-free server in `local-fixture/server.mjs` for every run. It listens at `http://127.0.0.1:3000` and exposes only deterministic fixture routes.
- `local-chromium` owns `tests/smoke`, `tests/accessibility`, `tests/visual`, and `tests/recorded`. Those files never run against an external URL.
- `PLAYWRIGHT_TEST_BASE_URL` configures external browser projects only. When it is set, optional Chromium, Firefox, WebKit, and mobile-Chrome projects ignore all local-fixture and authenticated files.
- Authenticated tests use the `*.authenticated.spec.ts` suffix and run only in `chromium-auth`. `E2E_AUTH_ENABLED=true` without an external base URL is a configuration error. The target must use HTTPS and either contain an explicit non-production hostname label or match `E2E_AUTH_ALLOWED_HOSTS` exactly.
- Auth setup is opt-in, uses non-production credentials from environment variables or CI secrets, and persists state only after a configured success selector or URL regex proves login.
- The authenticated regression wrapper loads `packages/web/.env` before its opt-in preflight while preserving explicitly exported values. The `chromium-auth` project disables traces, screenshots, video, performance capture, and persistent HTML/JUnit/Allure reporters because those artifacts can contain cookies, storage state, authenticated URLs, headers, assertion text, or private test data; authenticated CI keeps only the console list reporter.
- The committed local suites need no external URL, credentials, account, or service. The authenticated Media Planner suites remain explicit external checks.
- Playwright retries are disabled in every environment. Generated and recorded gates additionally execute each delivered test three times and fail on any skipped, failed, or flaky result.
- The visual suite is a deterministic layout/CSS contract and attaches a screenshot as evidence. It does not claim pixel-baseline comparison.
- Accessibility checks run Axe against the local fixture and are blocking.
- Chrome Recorder files under `recordings/*.json` are first-class contracts. Underscore-prefixed files are templates; an empty/template-only directory fails validation.
- The committed recorder pair is `recordings/checkout-confirmation.json` and `tests/recorded/checkout-confirmation.spec.ts`, targeting `/recorded-example/checkout`.
- Flow specs are authorized by deterministic schema, semantic, placeholder, and drift checks. Reviewer identity, dates, signatures, and interactive promotion state are not part of the generation policy.
- New, imported, or materially revised specs keep `NEEDS_REVIEW` markers until deterministic contract values are supplied; the normal quality gate fails closed while any marker remains.
- `--allow-draft` performs structural validation only and never authorizes generation or execution.
- `Generation Status | pending-generation` means no target test is claimed. Strict validation rejects both a missing generated target and a stale target beside a pending status.
- Generated tests are bound to their spec by behavioral SHA-256. Editorial Notes do not change that hash.
- Hand-written local tests without a flow header must be listed in `tests/.no-header-allowlist`.
- Page Objects own product locators. Raw CSS, positional locators, and other policy exceptions require an immediately preceding `locator-policy:exception` explanation.
- External state-mutating suites run with one worker. The test-data manager takes an in-process lease, snapshots original state, records its exact last write, and restores only when live state is still owned or already restored.
- The backend exposes no compare-and-swap for these mutations. Cross-process mutation of the same pinned session/channel is unsupported; divergence is reported and left untouched.
- `restoreMutatedTestData` restores manager-owned SKU, channel, and catalogue fields. `cleanupCreatedTestData` also deletes disposable plans created through an explicit `TestDataContracts` adapter, in reverse creation order. Automatic planning-session creation remains disabled and API-seeded suites require a pinned disposable `NECTAR_PLANNING_SESSION_ID`; the captured API still has no session-delete operation.
- Generated browser storage state and API-derived auth environment files are gitignored and written with owner-only file permissions; never archive or force-add them.
- Brand-linked SKU enumeration is implemented from the captured `planning_getCategories` query. `ensureBrandLinkedSkus` succeeds read-only when links already exist and can create missing links only when verified link and unlink adapters are both supplied. No per-SKU link/unlink operation exists among the 189 live-introspected mutations and `BrandInput` has no SKU-link list, so catalogue writes remain unavailable.
- Live schema introspection found `planning_savePartial/CompleteCampaignDetailsAndBudget`, `planning_savePartial/CompleteChannelsAndMedia`, and `planning_deletePlan(planId: ID!, briefId: ID!, advertiserId: ID!)`. They remain adapter blockers rather than executable writes: save guarantees only the returned plan `id` while `briefId`/`advertiserId` are nullable, delete requires all three identifiers, partial campaign input requires at least `campaignName` and `campaignStartDate` when supplied, and the exposed channel fields still lack verified enum/domain, units, date-format, merge, and rollback semantics.
- `setFeatureFlags` is implemented by the Playwright fixture through the existing `feature-flags` localStorage contract. Values are validated as boolean flags, applied to the current page, and installed for later navigations; `PlanningPage` preserves explicit overrides while supplying defaults for omitted planner flags.
- Store-volume bounds come from the live admin media configuration by default. Valid non-negative integer `E2E_MP_STORE_VOLUME_MIN/MAX` values remain supported overrides.
- Minimum campaign duration must be a positive integer; invalid `E2E_MP_DD_COMPETITION_PAGE_MIN_DURATION_DAYS` values fail before a test runs.
- `.ai-runs/`, auth state, reports, traces, screenshots, videos, and Allure output are runtime artifacts and must not be committed.
- CI quality gates run static review plus deterministic local Chromium suites. Authenticated regression is a separate opt-in, preflighted, serialized job.
- The root `npm test` aggregates UI unit tests, API unit tests, and the local web fixture suite. External authenticated tests remain opt-in.
